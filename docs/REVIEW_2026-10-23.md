# 在庫管理アプリ 全面レビューと受け入れ条件（2026-10-23）

全コード（backend 約4,800行・frontend 約2,000行）を読んで見つけた欠点と、**直った状態（受け入れ条件）** の一覧。
進め方は「この一覧を正解として先に書く → 失敗するテストを書く → 直す → 全テストを回す」。
テスト名・E2E の名前には下の番号（例 `B-03`）を入れて、どの条件を確かめているか追えるようにする。

凡例：🔴 データが壊れる・止まる／🟠 人が操作して困る・誤解する／🟡 使いにくい・保守の負債

## G. セキュリティ（2026-10-23 追加）

OWASP の考え方（入力・認証・セッション・出力・設定・依存）に沿って洗い出した。

| 番号 | 今の動き（問題） | 困る場面・攻撃 | 受け入れ条件 |
|---|---|---|---|
| G-01 🔴 | CSV・Excel の出力で、物品名などが `=` `+` `-` `@` で始まると Excel が**数式として実行**する（CSV/数式インジェクション） | 物品名を `=HYPERLINK(...)` にしておくと、出力を開いた人の PC で外部へ通信・情報が漏れる | CSV はその種の値の先頭に `'` を付ける。Excel（棚卸し・発注書）は文字列として書く |

### 確認して問題なかったもの
- SQL インジェクション：ORM と固定の列名だけ。検索の `%` `_` は文字扱い（B-15）。AI の SQL は読み取り専用・テーブル限定（E-02）。
- XSS：React が自動でエスケープし、`dangerouslySetInnerHTML` は使っていない。
- JWT：アルゴリズムは固定（`algorithms=[...]`）で `none` を受け付けない。ロールは毎回 DB から読む。無効化したユーザーはすぐ弾く。
- エラー：500 の中身（例外の詳細）は利用者に返さない（E-06）。本番は API ドキュメントを閉じる。
- 認可：管理者だけの API は `require_admin`、書き込みは USER 以上。他人の申請の編集・取消は不可（B-10・C-04）。
- 秘密情報：`.env`・DB・ログ・バックアップは Git に入っていない。Docker は root で動かさず、依存はハッシュ照合。
